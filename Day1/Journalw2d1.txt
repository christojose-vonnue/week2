Selectors are used to target a specific elemennts of a class/id to give customized style
Eg:

.classname {
    declarations;
    property:value;

    like -> color:red;

Types of selectors
-------------------
Universal selsctor 
*{
    declarations applies for every element;
}

Type Selector
article{
    property:value; //applies those styles for all articles
}

Class selectors

.classname{
    apply declarations for all elements with same class
}

Idenetity selector
#id_selector{
    apply styles but since its id we can use it only one time
}

Attribute selector

[data-type='primary' s/i]{
    color red;
    /* s and i makes the comparison of attributes case-sensitive/case-insensitive */
}

<div data-type="primary"></div>

[href*='example.com']       *     checks if string is in the url
[href^='example.com']       ^     checks if the url starts with the string
[href$='.com']              $     check if the url ends with the string

Specificity : https://web.dev/learn/css/specificity

If multiple styles are applied on same element, which style must be chosen?
This is dealt by specificity

Specificity is a triad of scores
 (  A   B   C )
Where 
A  -> id like specificity
B  -> class like specificity
C   -> element like specificity

SO WHEN STYLES CLASH, THESE TRAIDS ARE COMPARED
1st A is compared, if it tied then B then C

no specificity
    *{} and :not().. (arguments can also add specificity)


type or pseudo elements add specificity to C 
    div {} or ::selection ...

Class, Pseudo Class or Attribute selector add to B
    .class{} or button:hover{} or href$=['.com']

id adds to A
    #property{ }


if specificity is tied the TIE BREAKER IS THE SOURCE ORDER LAST FORMATTING WINS

•​ Why is box-sizing: border-box almost always the better choice? When would you NOT use it?
Because as we develop and evolve our website our overall height and width will be fixed, we don't want the layout to be changed as we change maybe the size of the border or maybe adding extra padding. We would not use border box in situation where we don't want the content box to be constricted further or when we can tolerate sufficient changes to the boxes. 


•​ What is the difference between :focus and :focus-visible, and why does it matter for keyboard users?
:focus focuses or applies the style we define when the keyboard user simply enters or focuses the element, but :focus-visible is more intelligent and by default behavior it does not applies styles to elements in which we cannot enter data.
